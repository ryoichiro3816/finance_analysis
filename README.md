# Money Forward CSV Analysis 要件定義書

## 1. 背景・目的

Money ForwardからダウンロードしたCSVファイルを取り込み、長期的にデータを蓄積する。
蓄積した家計・資産・入出金データを、Money Forward標準機能とは異なる独自の視点で分析し、HTMLレポートとして出力する。

## 2. 想定ユーザー

- 個人利用者
- Money ForwardのCSVを定期的にダウンロードできる人
- 支出、収入、資産推移、カテゴリ別傾向などを自分の観点で確認したい人

## 3. 対象データ

### 3.1 入力ファイル

- Money ForwardからダウンロードしたCSVファイル
- 初期対象は「収入・支出詳細」CSV
- 文字コードはUTF-8 BOM付きCSVを想定する
- 日付形式は `YYYY/MM/DD` を想定する
- 複数回取り込みを前提とする
- CSV原本は `data/csv/` に蓄積する
- 年別や期間別にダウンロードした複数CSVを同じディレクトリに保存できること
- `data/csv/` はMoney Forwardから取得した原本置き場とし、取り込み後も削除しない
- DB側では取り込み済みファイルと取り込み済み明細を管理する

### 3.1.1 確認済みCSV仕様

`data/csv/収入・支出詳細_2026.csv` で確認した列は以下。

- 計算対象
- 日付
- 内容
- 金額（円）
- 保有金融機関
- 大項目
- 中項目
- メモ
- 振替
- ID

確認したCSVの概要。

- データ行数: 681件
- 対象期間: 2026/01/01から2026/07/01
- ID列の重複: なし
- メモ列: 全件空欄
- 計算対象=1: 602件
- 計算対象=0: 79件
- 振替=0: 602件
- 振替=1: 79件

標準の収支分析では、原則として `計算対象=1` かつ `振替=0` の明細を対象にする。
ただし、振替明細もDBには保存し、別途確認できるようにする。

### 3.2 想定する主な項目

- 取引日
- 内容、摘要、メモ
- 金額
- 大項目カテゴリ
- 中項目カテゴリ
- 口座、カード、金融機関
- 振替判定
- 計算対象フラグ
- Money Forward ID

金額はMoney Forward CSVの `金額（円）` をそのまま保存する。
プラス金額を収入、マイナス金額を支出として扱う。

## 4. スコープ

### 4.1 初期スコープ

- CSVファイルの取り込み
- 取り込んだデータの重複排除
- SQLiteなどのローカルDBへの保存
- DBに蓄積したデータを使った集計
- HTMLレポートの生成
- ローカル環境での実行

### 4.2 初期スコープ外

- Money Forwardへの自動ログイン、スクレイピング
- CSVの自動ダウンロード
- 複数ユーザー対応
- Webアプリとしての常時起動
- クラウド同期
- 銀行・証券APIとの直接連携

## 5. 機能要件

### 5.1 CSV取り込み機能

- ユーザーが指定したCSVファイルを読み込めること
- デフォルトでは `data/csv/` 配下のCSVを取り込み対象にできること
- 複数ファイルを連続で取り込めること
- 複数年分、複数期間分のCSVを蓄積して取り込めること
- 同じCSVを再取り込みしても、同一取引が重複登録されないこと
- Money Forward CSVの `ID` を第一候補の一意キーとして利用すること
- `ID` がないCSVに備えて、行内容から算出したハッシュでも重複判定できる設計にすること
- 取り込み結果として以下を表示すること
  - 読み込み件数
  - 新規登録件数
  - 重複スキップ件数
  - エラー件数
- 文字コードや日付形式の違いに対応できる設計にすること
- CSVの列名変更に備え、列マッピングを調整できる余地を残すこと

### 5.2 データ蓄積機能

- 取引明細をDBに保存できること
- 取り込み元ファイルの情報を保存できること
- 取り込み元ファイルのパス、ファイル名、ファイルハッシュを保存できること
- 元CSVの値を可能な限り保持すること
- 分析用に正規化した値も保存できること
- 登録日時、更新日時を保存すること
- CSV原本の保存とDBへの正規化保存を分けて扱うこと

### 5.3 データ補正・分類機能

確認済みCSVでは未分類の支出が大きいため、独自分類ルールは初期段階から重要な機能として扱う。

- 特定の摘要や店舗名に基づく独自カテゴリ付与
- Money Forwardカテゴリとは別の分析用カテゴリ付与
- 振替、投資、クレジットカード引き落としなどの除外ルール
- 手動補正したカテゴリやメモの保存
- 元のMoney Forwardカテゴリは保持し、分析用カテゴリを別カラムまたは別テーブルで管理する

### 5.4 分析機能

初期レポートでは以下の分析を対象とする。

- 月別の収入、支出、収支
- カテゴリ別支出
- 支出上位カテゴリ
- 支出上位明細
- 固定費と変動費の比較
- 前月比、前年同月比
- 年間累計
- 計算対象外、振替明細の件数と金額
- 未分類明細の抽出

将来的な分析候補は以下とする。

- サブスクリプション支出の抽出
- 特定店舗・サービスへの支出推移
- 資産残高推移
- 投資関連の入出金分析
- 税金、保険、医療費などの年間集計
- 予算に対する実績比較
- 異常値検出

### 5.5 HTMLレポート生成機能

- DBの内容をもとにHTMLファイルを生成できること
- レポート対象期間を指定できること
- 生成したHTMLはブラウザで単体表示できること
- 初期レポートに以下を含めること
  - 対象期間
  - サマリー
  - 月別収支表
  - カテゴリ別支出表
  - 支出ランキング
  - 簡単なグラフ
- CSSを含め、見やすいレイアウトにすること
- 将来的にテンプレートを差し替えられる設計にすること

## 6. 非機能要件

### 6.1 実行環境

- ローカルPCで動作すること
- 初期候補言語はPython
- 初期候補DBはSQLite
- HTML生成はテンプレートエンジンを利用する

### 6.2 セキュリティ・プライバシー

- 家計データはローカルに保存する
- 外部サービスへデータ送信しない
- DBファイル、CSVファイル、生成レポートをGit管理対象から除外する
- 個人情報を含む可能性があるため、サンプルデータ作成時は匿名化する

### 6.3 保守性

- CSV取り込み、DB操作、分析、HTML生成を分離する
- 分析ロジックを後から追加しやすい構成にする
- CSVフォーマット変更に対応しやすい構成にする

### 6.4 性能

- 個人利用を前提とし、数万から数十万件程度の取引明細を扱えること
- HTMLレポート生成は数秒から十数秒程度で完了することを目標とする

## 8. コマンド仕様案

初期実装はCLIとして設計する。

```bash
# CSVを取り込む
python -m finance_analysis import path/to/money_forward.csv

# data/csv配下の複数CSVを取り込む
python -m finance_analysis import data/csv/*.csv

# デフォルトのCSV置き場をまとめて取り込む
python -m finance_analysis import

# HTMLレポートを生成する
python -m finance_analysis report --from 2026-01-01 --to 2026-12-31 --output reports/2026.html

# DBの概要を確認する
python -m finance_analysis summary
```
